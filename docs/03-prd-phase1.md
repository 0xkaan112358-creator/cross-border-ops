# 跨境运营 AI 助手 · 产品需求文档（v0.1，已确认）

> 确认日期：2026-11-24

## 1. 背景与目标

公司的库存数据分散在多个仓库和系统里，补货靠 Excel 和个人经验。员工查库存、查跨境规则都要找人或翻文档。客服重复问题多，还要值夜班。

本项目要做一个内部 Web 工具，一期达成三个目标：

1. **补货**：所有 SKU 的库存状态一屏可见，系统自动算出"该不该补、补多少、什么时候发"，并说明理由。
2. **查询**：员工用自然语言就能查库存，也能查跨境物流、平台规则、认证标准等知识，回答注明出处。
3. **客服**：AI 自动筛选和分类客户消息，简单问题直接回复，困难工单转人工，同时附上摘要和建议回复。

## 2. 使用角色

| 角色 | 主要使用的功能 |
|---|---|
| 计划 / 运营 | 库存总览、补货建议、预警、参数配置 |
| 采购 / 财务 | 查看补货计划和资金占用 |
| 全体员工 | 库存问答、跨境知识问答 |
| 客服专员 | 处理转人工的工单，审核 AI 回复 |
| 客服主管 / 管理员 | 自动回复规则、知识库维护、抽检 |

## 3. 功能需求

### 模块 A：库存与补货中心（核心）

**A1. 统一库存视图**

- 按 SKU 和站点汇总库存：国内仓、在产（已下单未出厂）、在途（头程运输中）、海外仓、FBA 可售、FBA 入库中。
- 为每个 SKU 计算**可售天数**，并给出状态标签：
  - 🔴 断货风险：可售天数小于总提前期。
  - 🟠 需补货：可售天数小于"总提前期 + 安全天数"。
  - 🟢 健康。
  - 🔵 冗余：可售天数超过设定上限，或库龄超过阈值。
- 支持按站点、状态、负责人筛选，以及按 SKU 或关键字搜索。

**A2. 销量预测（一期用可解释的统计方法）**

- 日均销量取近 7、14、30 天的加权平均，**剔除断货日**，避免断货期把需求算低。
- 支持人工配置季节系数和大促系数，例如 Prime Day 当月乘以 1.8。
- 预留后续升级为机器学习模型的接口。一期刻意不做复杂模型：先保证数据准、逻辑透明，员工才敢用。

**A3. 补货建议**

- 总提前期 = 生产周期 + 头程运输时间 + 入仓上架时间（按 SKU 和运输方式配置）。
- 建议补货量 = 日均预测销量 ×（总提前期 + 安全天数 + 覆盖周期）−（FBA 可售 + 在途 + 在产 + 海外仓可调拨），再按箱规和最小起订量向上取整。
- 给出建议的下单日期和发货日期。断货风险高时，提示"海运 + 少量空运"的组合方案。
- **每条建议附一段大模型生成的白话解释**，例如："日均 42 件，当前可售 38 天，海运全程需 55 天，下月有大促，建议本周下单 2400 件。"
- 计划员可以修改数量并填写修改原因，系统留存记录，供日后复盘和优化模型。
- 补货计划可以导出为 Excel。

**A4. 预警**

- 每天自动生成预警清单：新增断货风险、需补货、冗余库存。
- 在首页集中展示。是否推送到企业微信或钉钉，作为待确认项。

### 模块 B：智能问答助手

**B1. 库存问答**

- 员工用自然语言提问，例如："美国站 XX 系列还能卖几天？""哪些 SKU 下个月会断货？""在途的货什么时候到？"
- 技术上通过大模型调用查询工具获取真实数据后再回答，**不允许模型凭空编造数字**。

**B2. 跨境知识问答（合规只做到"查得到"）**

- 管理员上传文档（PDF、Word、Markdown），系统自动切片并建立索引。文档类型包括平台规则、物流和关务知识、各国认证标准说明、公司内部 SOP。
- 回答时附上引用来源（文档名和段落），知识库中找不到答案时明确说"不知道"。
- 一期不做侵权检测、专利检索等深度风控。

### 模块 C：智能客服工单

**C1. 消息接入**

- 一期支持通过 CSV 批量导入，或手动粘贴客户消息，用于验证分类和回复效果。
- 二期再对接邮箱（Amazon 买家消息可以转发到邮箱）和独立站。

**C2. AI 自动筛选**

每条消息自动识别以下四项：

- **意图**：物流查询、产品使用咨询、退换货申请、质量投诉、索赔或差评威胁、其他。
- **难度**：简单或困难。
- **紧急程度**：高、中、低。
- **情绪**：平和、不满、愤怒。

同时自动识别语种，并给出中文翻译。

**C3. 分流规则**

满足以下全部条件时，判定为"简单问题"，由 AI 直接回复：

- 意图属于可自动处理的类型（物流查询、知识库能命中的使用咨询）；
- 分类置信度达到阈值；
- 客户情绪不是"愤怒"；
- 不涉及退款、补发等资金操作。

其余一律转入**人工工单队列**，按紧急程度排序。每个工单附 AI 摘要和中外对照的建议回复，客服修改后一键采用。

- 物流类回复会调用订单和物流数据查询，不靠模型猜测。
- 回复发出前自动检查违规话术，比如索要好评、引导站外交易。
- 管理员可以配置"哪些意图允许自动回复"以及置信度阈值。

**C4. 客服统计**

- 统计自动解决率、各类问题占比、平均处理时长，作为后续优化的依据。

## 4. 一期明确不做

- 直连 Amazon SP-API 或 ERP 的实时同步（一期先用导入方式，二期再对接）
- 机器学习销量预测模型、运筹优化求解
- 侵权检测、专利和商标检索、申诉材料生成
- 自动执行退款、补发等资金操作
- 移动端 App（网页做响应式适配，手机可以访问）

## 5. 技术方案概要

| 层 | 选型 |
|---|---|
| 前端和后端 | Next.js + TypeScript + Tailwind + shadcn/ui |
| 数据库 | PostgreSQL + pgvector（同时存业务数据和知识库向量） |
| 大模型 | 通过统一接口接入，可切换供应商；未配置密钥时使用模拟模式，演示流程不受影响 |
| 数据接入 | 一期提供 Excel/CSV 导入模板 + 一套示例数据 |
| 权限 | 内部登录，区分普通员工、客服和管理员 |

## 6. 分期规划

- **一期（MVP）**：上面 A、B、C 三个模块，用导入数据跑通完整流程。
- **二期**：对接 ERP 或 Amazon SP-API 自动同步数据，邮箱接入客服消息，企业微信或钉钉推送，自动回复从"人审"过渡到"自动发送 + 抽检"。
- **三期**：机器学习预测模型，多仓分配和运输方式优化，客服问题反哺 Listing 和产品改进。

## 7. 成功指标

- 计划员每周做补货决策的耗时
- 断货次数和冗余库存金额
- 员工查询库存和规则的平均耗时（找人问 → 直接问系统）
- 客服自动解决率、首次响应时间

## 9. 一期实现说明

以下是一期实际实现与本文档的差异和补充，供后续迭代参考。

- **知识库检索**：没有使用 pgvector 向量检索，改用 BM25 关键词检索（中文按两个字一组切分）。示例资料上能找准出处；资料量变大后再升级为向量检索。
- **客服发送**：一期没有接入亚马逊消息接口，“发送”是复制回复并把工单标为已回复。“简单问题自动发送”开关已放在设置里，标为二期、暂不可用；工单页提供“草稿采纳率”指标，作为开启自动发送的判断依据。
- **预警推送**：预警集中展示在首页，暂未推送到企业微信或钉钉。
- **模拟模式**：未配置大模型密钥时，问答、分类和回复由规则与模板生成，只能识别常见说法；模拟模式下非英语的产品咨询会转人工。
- **权限**：Cursor 团队管理员自动成为管理员，其他成员由管理员在“设置 > 成员角色”中按邮箱指定为客服或管理员，其余登录用户为普通员工。
