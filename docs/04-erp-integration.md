# ERP 对接说明

对接对象是《模拟ERP接口文档》v5.1.0（OpenAPI 3.0.3，179 个接口）。它是独立的模拟系统，接口路径和字段仿照领星。

## 确认记录（2026-11-24）

| 问题 | 决定 |
|---|---|
| 优先使用哪类接口 | 领星风格接口，以后换成真正的领星时改动最小 |
| 同步方式 | 管理员在“数据导入”页手动点“立即同步” |
| 客服工单 | 不同步 ERP 工单（ERP 工单只有标题，没有消息正文），客户消息继续手动录入或用表格导入；订单物流照常同步 |
| ERP 自带补货建议 | 暂不显示，只用本系统的补货计算 |
| 首次同步 | 先清空示例业务数据，只保留 ERP 数据 |

## 认证与连接

- 用 ERP 管理员账号和密码调用 `POST /api/auth-server/oauth/access-token` 换取 token，之后所有请求带 `Authorization: Bearer <token>`。token 过期前用 refresh token 续期，续期失败时重新登录。
- 公网模拟 ERP 使用自签名证书。系统不会关闭证书校验，而是通过 `ERP_TLS_FINGERPRINT` 固定证书的 SHA-256 指纹：先取回服务器证书并比对指纹，不一致则拒绝连接，一致时把这张证书作为唯一信任的证书，再做完整的 TLS 校验。

## 接口与数据对应

| 本系统数据 | ERP 接口 | 取值规则 |
|---|---|---|
| SKU 主数据 | `GET /api/v1/products` | 品名、类目、负责人、成本、起订量、采购周期（作为生产周期）、箱规。领星风格的产品接口在这份文档里没有字段定义，所以这一项用 ERP 自有接口 |
| 仓库类型 | `GET /api/v1/warehouses` | 按仓库类型区分本地仓和海外仓，按国家确定海外仓对应的站点 |
| FBA 可售 / 入库中 / 在途 / 超龄 | `fbaWarehouseDetail` | 可售取“总可用库存”（可售 + 待调仓 + 调仓中）；入库中取 `afn_inbound_receiving_quantity`；在途取 `afn_inbound_shipped_quantity`；超龄取 181 天以上各库龄段之和 |
| 国内仓 / 海外仓 | `inventoryDetails` | 可用量 + 调拨在途。先按仓库所在国家判断：在美、英、德、法、意、西的仓库（海外仓、自营仓、平台仓）计入该站点的海外仓，在中国的计入国内仓；没有国家时再看仓库类型。FBA 仓跳过。国内仓库存没有绑定店铺时，计入该 SKU 近 60 天销量最高的站点 |
| 在产 | `purchaseOrderList` | 近 365 天创建、状态为“待下单（已审核）”或“待到货”的采购单的待到货量。真实 ERP 的数字状态为空，只有中文状态，这时按中文状态判断：待下单、待到货、部分入库计入，其余不计入。待到货量优先取明细的 `quantity_receive`；为 0 或空时，用“实际采购量（`quantity_real`，没有时依次用 `quantity`、`quantity_plan`）− 到货入库量（`quantity_entry`）”计算 |
| 在途货件 | `/api/v1/shipments` + `/api/v1/fba-delivery-orders` | 货件只有表头（国家、物流方式、预计到货），SKU 明细在 FBA 发货单里，两者按货件号关联。每个 SKU 的在途数量 = 已发 − 已收；真实 ERP 的发货单明细只有数量、没有逐个 SKU 的已收数量，这时把整单的“已发 − 已收”按各 SKU 数量比例分摊。没有发货时间的（如待配货、待发货）、已完成、已关闭（亚马逊状态 CLOSED）、已取消、作废、草稿的发货单不计入；已收过货或状态为签收、到仓、入库中的显示为“已到仓·入库中”。没有对应发货单的货件拿不到 SKU 明细，不计入，并在同步结果中提示 |
| 每日销量、订单物流 | `mws/orders` | 近 60 天订单，剔除已取消订单后按本地 SKU × 站点 × 站点日期汇总销量。订单状态同时识别中文和英文写法，统一为已发货、部分发货、待发货、待审核、已取消 |

### 店铺与站点

ERP 用店铺 ID（sid）区分店铺，本系统按站点计算。系统按以下顺序识别店铺所属站点：订单的销售渠道（如 Amazon.de）、店铺名称中的国家信息。不在美、英、德、法、意、西范围内的店铺，相关数据跳过，并在同步结果中提示。

共享仓（sid 为 0）的库存按各站点近 60 天销量比例分摊，可售、入库中、在途和超龄库存都按同一比例：欧洲共享仓分摊到德、法、意、西，没有销量时计入德国站；北美共享仓计入美国站。这套模拟 ERP 不支持 `query_fba_storage_quantity_list`（接口文档标为 unsupported，传入会返回 400），所以拿不到共享仓按店铺拆分的数量。

## 同步规则

- 先拉取全部数据，再在一个数据库事务里写入。任何一步失败，现有数据都保持不变。
- 首次同步清空示例业务数据（SKU、库存、销量、货件、订单、客服工单、补货记录），知识库和参数设置不受影响。之后的同步：
  - 库存和在途货件整体替换为 ERP 最新数据。
  - 近 60 天销量按 ERP 重算。
  - 订单按订单号更新。
  - 本次没有出现在 ERP 中的 SKU × 站点从库存列表中隐藏。
- 头程时效优先用 ERP 历史货件实测：
  - 取同时有发货时间和签收时间的 FBA 发货单，按站点 × 运输方式（海运/空运）计算“签收 − 发货”的天数，取中位数。中位数不受个别异常票影响。
  - 至少 3 票才采用；海运只取 10～90 天、空运只取 2～30 天的样本，排除录错日期的单据。运输方式只认明确写了海运或空运的单据，不按天数猜。
  - 样本不足时按站点默认值：美国海运 30 天，欧洲 40 天，空运 10 天。上架时效 ERP 没有记录，统一 10 天。
  - 在“SKU 主数据”表格里手动填写过的时效标为“手动填写”，之后同步不会覆盖。库存详情页的“全程提前期”会注明海运时效来自哪里（站点默认值、ERP 历史货件实测或手动填写）。
  - 实测结果显示在同步结果的“头程时效实测”里。
- 断货日按销量推断（ERP 订单本身不标记断货）：
  - 对每个 SKU × 站点，找出近 60 天里连续没有销量的日子。
  - 用其余有货日的日均销量 λ 估算：正常有货时，连续 k 天一件都没卖出的概率约为 e^(−kλ)。当 k × λ ≥ 4（概率低于 2%）时，判定这段为断货。
  - 判定后从有货日里去掉这些日子，重新计算 λ，反复几轮直到结果稳定，避免长时间断货把日均拉低、导致漏判。
  - 当前 FBA 可售为 0 时，截至昨天的那段零销量直接判定为断货。
  - 断货日在补货计算中剔除，销量图上以红色背景标出；同步结果显示“推断的断货日”明细。
  - 销量本来就低的 SKU（例如日均 0.5 件）需要连续 8 天无销量才会判定，避免把正常的零星销售误判为断货。
- 每次同步都会记录在“数据导入”页，包括各类数据条数、需要留意的数据和店铺与站点的对应关系。

## 已知限制

- 断货日是按销量推断的，不是 ERP 记录的。断货只持续一两天、或销量本来就低的 SKU 可能识别不出来；反过来，因下架、listing 异常导致的零销量也会被当作断货。
- 订单接口没有承运商信息，客服回复中只引用追踪号和预计送达日期。
- 订单状态为“待发货”“部分发货”“待审核”“已取消”的物流咨询会转人工处理。
- 2026-11-24 用真实数据核对的结果：
  - 这套 ERP 只有美国站。订单的销售渠道为空，店铺 ID 统一为 1，所以站点按店铺名称识别。
  - 订单状态是中文。
  - 领星风格的发货单接口（`getInboundShipmentList`）没有数据，所以在途货件明细改从 ERP 自有的货件和 FBA 发货单接口获取（2026-11-24 确认）。补货计算用的在途数量仍来自 FBA 库存的“在途”字段，货件明细只用于首页、库存详情和智能问答，两者不重复计算。
  - 接口文档没有写 FBA 发货单 `item_list` 的字段。同步时 SKU 依次识别 `sku`、`local_sku`、`msku`、`seller_sku`；已发数量依次识别 `shipped_qty`、`quantity_shipped`、`ship_qty`、`quantity`、`qty`、`num`；已收数量依次识别 `received_qty`、`quantity_received`、`receive_qty`、`receive_num`。真实字段名显示在同步结果的“ERP 原始数据”里，用于核对。
  - 每页最多返回 500 条，同步按 ERP 报告的总数翻页。
- 同步耗时控制：
  - 平台单次执行上限是 5 分钟。拉取超过 200 秒后不再发起新请求，同步标记为失败，数据保持不变。
  - 同步过程中，每个接口的页数、条数和耗时实时写入同步记录，页面每 3 秒刷新一次；失败时保留这份进度，用来判断卡在哪个接口。
  - 超过 6 分钟仍显示“同步中”的记录，说明进程已被平台中断，系统会自动标记为“已中断”，之后可以重新同步。
  - 接口忽略翻页参数、重复返回同一页时，同步立即停止并提示是哪个接口。
